常见问题

当前适用版本：0.4.0-beta.62

这一页只回答容易被反复问到的边界：兼容范围、数据写到哪、分组会不会动日志、归档配置怎么恢复、多窗口怎么同步，以及报 bug 要带什么资料。操作步骤不在这里重复。

摘要

① 只支持社区 Stable 2.0.18 与官方桌面 0.2.1.0 / 0.2.2.0；Beta 与 NEXT 不承诺兼容。
② 分组不写 workspace.json、不改会话日志；只有你或开启会话操作的 AI 才会改标题与归档。
③ 归档配置目前只能改注册表恢复；报 bug 至少给插件版本、DSH 版本、复现步骤与截图。

兼容与数据

1. 支持哪些桌面版本

  1. 社区版 DSH Desktop Stable 2.0.18（内置 DSH 0.2.1-rc.2）：已验证。
  2. 官方 DeepSeek Harness 桌面版 0.2.1.0（DSH 0.2.1-rc.5；.60 另含维护者桌面窗口验收）：已验证。
  3. 官方 DeepSeek Harness 桌面版 0.2.2.0（DSH 0.2.2-rc.1；.61 隔离 A+）：已验证。
  4. 社区版 Beta 与 NEXT（-next）不官方支持、不承诺兼容；即使能加载也不算通过。
  5. Windows 是唯一做过真实 DSH UI 验证的平台；Linux/macOS 目前只有 CI 的 Node 层证据。

2. 数据会不会写进 workspace.json

  1. 分组本身不写 workspace.json：它只写 storages/dsh-session-grove.json、dsh-session-grove.profiles.json 与 profiles/<id>/。
  2. 官方工作区注册表 storages/workspace.json 只在会话归档状态变化时由 DSH 更新，插件不直接改它。
  3. 你在界面归档会话、或开启 controlSessions 让 AI 归档，走的是 DSH 的会话状态路径，效果与手动归档相同；标题变更也一样。
  4. 卸载插件后官方视图恢复；分组文件与本地偏好保留，重装还能接着用。

3. 分组会不会影响会话日志

  1. 不会。分组只决定显示位置，会话仍属于原工作区，日志不由插件读写。
  2. 归档一个分组不归档其中的会话，也不删文件；删除分组只移除分组层级，非空时先把直接会话与子组转到目标组。
  3. 归档或取消归档会话是 DSH 的会话状态，日志仍在；归档不是删除。
  4. 分叉由宿主执行并产生新的子会话，分组只决定它显示在哪个组。

恢复与多窗口

4. 归档配置怎么恢复

  1. 归档只是把配置从切换列表隐藏，配置文件与会话都保留。
  2. 目前没有恢复按钮，需要关闭 DSH 后编辑 storages/dsh-session-grove.profiles.json。
  3. 找到该配置的 "archivedAt"，把时间戳改成 null；其他字段保持不变。
  4. 保存后启动 DSH，配置重新出现在切换浮层；浮层只列未归档配置。
  5. 改前先复制注册表；JSON 写坏会让配置操作整体降级。

5. 多窗口 active 配置如何同步

  1. active 是 DSH 实例全局的，不是每个窗口一套；所有窗口跟随同一个配置。
  2. 一个窗口切换后，其他窗口通过事件流自动刷新，并提示「另一窗口已切换到…」。
  3. 两个窗口同时写同一份文档时用 revision 比较：一个成功，另一个收到 409 并加载最新版本，提示「分组数据已在别处更新」。
  4. 折叠状态、侧栏宽度与弹窗位置是单窗口本地状态，不跨窗口实时同步。
  5. 没有「每个窗口独立 active」的开关。

报 bug

6. 发现 bug 该提供什么信息

  1. 插件版本：插件 → 自由分组 → 详情头部，形如 v0.4.0-beta.62；分组视图的「视图选项」底部也有同样一行。
  2. DSH 桌面端名称与版本，以及内置 DSH core 版本（例如 Stable 2.0.18 / 0.2.1-rc.2）。
  3. 复现步骤：从哪个视图开始、点了什么、期望与实际；能否稳定复现。
  4. 截图或录屏；涉及数据时附 storages/ 下相关 JSON，先去掉路径里的用户名与会话标题。
  5. 拖拽或布局问题可临时打开「拖拽诊断」复现，附 storages/dsh-session-grove.diagnostics.ndjson；它不记录会话正文。

版本与包名都在插件详情头部，下图红框就是版本号。

注意

不要把整个 ~/.dsh 打包发出去。最小化到相关 JSON 与截图，先移除路径中的用户名、工作区路径与会话标题。

展开：beta 版本怎么描述才够复现

  • 只写版本号不够：同一版本号在不同桌面族里可能装的是不同 DSH core。
  • 写清桌面族与内置 DSH 版本，例如「社区 Stable 2.0.18 / 0.2.1-rc.2」或「官方 0.2.2.0 / 0.2.2-rc.1」。
  • 如果问题只在某个桌面族出现，直接写明；.62 的官方 A+ 没有重跑，不等于官方族已覆盖。
