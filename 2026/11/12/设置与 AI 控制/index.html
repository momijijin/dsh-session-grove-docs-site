设置与 AI 控制

当前适用版本：0.4.0-beta.62

设置卡不在分组视图里，而在 DSH 插件管理器的插件详情第一层，五个开关默认全关。控制分成两层：AI 控制接口 决定 AI 能不能读写分组，允许会话操作 再单独放开会话改名与归档；只整理分组时后者保持关闭。

摘要

① 插件 → dsh-session-grove 详情第一层就是「自由分组设置」，改完不用重启（技能安装除外）。
② 打开 AI 控制接口，AI 才能调用 session_grove_control；允许会话操作才能改标题与归档，且依赖总开关。
③ apply 必须带 plan 返回的同一 planHash 与 baseRevision；多配置还必须显式 profileId，且不能替你切换当前配置。

设置卡

1. 打开插件详情第一层

  1. 在 DSH 左侧栏点「插件」，等插件列表加载完。
  2. 点「自由分组」（包名 dsh-session-grove）进入详情页。
  3. 配置就在第一层，标题是「自由分组设置」；不需要展开下面的「包含的组件」。
  4. 五个开关默认关闭；每行右侧的 ⓘ 会展开「功能 / 何时开启 / 安全风险 / 其他影响」四段说明。

这一步看到的就是设置卡本身，下图是五个开关与底部的技能修复入口。

2. 五个开关分别管什么

  1. 拖拽诊断：显示拖拽 HUD，并把分组操作与拖拽事件写进本地 NDJSON；只在排查问题时临时开。
  2. 弹窗布局探针：给弹窗几何调试用的临时探针；生产环境不要开。
  3. AI 控制接口：总开关；打开后 AI 才能通过 session_grove_control 读取与提交分组。
  4. 允许会话操作：允许 AI 改会话标题、切换归档状态；总开关关闭时这一行不可点，并提示「需要先开启 AI 控制接口」。
  5. 允许破坏性操作：允许 AI 删除分组；打开时先弹危险确认，必须点「我理解风险，开启」。

3. controlSessions 到底改变什么

  1. 关闭时，AI 只能动分组：新建、改名、移动会话归属、归档分组都不会碰会话本身。
  2. 打开后多两类动作：改名（可用 expectedTitle 校验当前标题）与归档/取消归档（可用 expectedArchived 校验当前状态）。
  3. 改的是 DSH 核心会话状态，不是分组文档：标题立刻变，归档后行变暗并进入归档筛选。
  4. 归档正在运行的会话必须显式传 stopActivity: true；没有这个参数会直接拒绝，不会先停掉会话。
  5. 关掉总开关会连带关掉「允许会话操作」；只开总开关、不开会话操作时，会话动作返回 session-controls-disabled。
注意

改名没有撤销入口，归档可以用「取消归档」恢复。不要把会话操作开给来源不明的提示词或自动化；只整理分组时保持关闭。

4. AI 控制接口的边界

  1. 先 state 或 resolve 拿 revision 与目标 groupId；plan 只算变化，返回 changes 与 planHash，不写盘。
  2. apply 必须带同一个 planHash 与 baseRevision；中途文档被别人改过就冲突，需要重新 plan。
  3. 有多份未归档配置时，plan/apply 必须显式传 profileId；只有 default 时可以省略。
  4. planHash 包含 profileId：为一份配置生成的 plan 不能套到另一份。
  5. 没有切换 active 的动作：AI 可以读写指定配置，但你当前看哪套配置仍由你在浮层里点。
  6. 幂等键只属于 HTTP 调试接口（idempotencyKey，按 profileId:key 去重）；原生工具没有重放缓存，重复 apply 会按 revision 冲突处理。

用起来

5. 让 AI 改分组

  1. 先打开「AI 控制接口」；需要改标题或归档，再打开「允许会话操作」。
  2. 在会话里直接说目标，例如「把会话侧栏移到界面改造下面」，AI 会调用 session_grove_control。
  3. 要求它先给出 changes 与 planHash，确认后再用同一个 planHash 和 baseRevision 执行 apply。
  4. 不需要命令行、HTTP、Cookie 或 token；设置页点开关就够了。

6. AI 控制技能损坏时

  1. 总开关打开后，宿主下次启动时会把 session-grove-control skill 安装到 <dshHome>/skills/；刚打开还没重启就先点一次修复。
  2. 如果技能文件被删或损坏，到详情页底部「AI 控制技能」点「校验 / 重装技能」。
  3. 成功会显示「技能已可用」；同名用户文件不会被覆盖，会提示「该 skill 是用户文件，已拒绝覆盖」。
  4. 总开关关闭时点它会失败；先打开 AI 控制接口再修复。

展开：生效范围与门禁细节

  • 五个开关是宿主侧的插件配置，对所有窗口生效，与分组配置（profile）无关。
  • 关闭总开关后控制路由仍注册，但返回 404 control-disabled；doctor 仍可只读调用。
  • 诊断文件固定写到 <dshHome>/storages/dsh-session-grove.diagnostics.ndjson，超过 8 MiB 会先清空再写，不做自动轮转。
  • 原生工具在 Host 进程内执行，不经过浏览器 fence；HTTP 路由仍受宿主浏览器会话保护。
