0.4.0-beta.62：分组归档与递归结构锁

归档从「会话」扩展到了「分组」：整组连同子分组一起收进归档，视图里可以按三态筛选，归档后的整棵子树进入只读结构锁。它不会级联修改会话的归档状态，也不改 DOC_VERSION；搜索和头部计数共用同一套可见性规则。

摘要

① Group.archived 是新增可选布尔，缺失读 false，DOC_VERSION 保持 1。
② 视图选项新增分组三态 hidden | all | only，与会话三态独立。
③ 生效归档的整棵子树冻结；提交前不变量拦截结构改动，失败返回 archive-frozen（409）。

改了什么

核心是三条：分组自己可以归档、归档范围按整棵子树计算、提交前用不变量守住结构。

  • 分组归档：分组新增归档标记，整组连子分组一起收进归档。
  • 第二套三态：视图选项多出分组归档三态，与会话三态各自独立。
  • 递归结构锁：生效归档的整棵子树冻结，结构类操作一律禁用。
  • 归档开关本身永远合法：归档不级联到会话或子分组，容器里的会话仍可单独操作。
  • 提交前状态不变量：以提交前的文档比对，归档前已存在的组只允许改归档标记。
  • 拖拽与提交同一套规则：拖拽判定与提交校验共用谓词，非法落点直接拒绝。
  • 宿主与控制接口：宿主写入前校验并继承缺失标记，违约返回明确错误。
  • 界面与语言资源：两段三态与锁定样式就位，各语言词典同步补齐。

注意

「取消归档 + 编辑」不能在同一次提交里完成，必须拆成两次；「归档 + 编辑」是合法的。归档开关本身不会级联到会话或子分组。

展开：契约、筛选与锁的实现细节

  • 字段与校验：Group.archived 是新增的可选布尔值，缺失按 false 读，非布尔值会被校验拒绝（group-archived-type:<id>）；生效状态是 effectiveArchived = own || any archived ancestor，archivedBy 记录最近的归档祖先，只派生、不持久化；归档标记按配置独立保存，不写进配置注册表；生效归档按祖先链计算，损坏文档的遍历做了防环。
  • 三态语义：hidden 剪掉归档子树但保留仍然存活的祖先；all 全部渲染；only 只渲染生效归档的组，以及通向它们的「仅标题」祖先，同时隐藏未分组；三态存储在 dsh-session-grove.archive.groups.v1，组内仍按会话筛选过滤。
  • 结构锁范围：生效归档的整棵子树被冻结，标题、图标、颜色、colorHex、父级、兄弟序号、sessionIds 顺序和直接子组顺序都不能改；归档组本身、以及含归档后代的组不能移动或删除；往归档目标里插入、或间接移动归档锚点的兄弟序号，都会被拒绝；页面上的锁/包含归档徽标统一为 16px。
  • 会话级操作：归档开关本身永远合法，不级联到会话或子分组，也不会调用 archiveSession；容器里的会话仍可打开（自身未归档时）、改名、切换归档、复制 ID；拖拽、重排、移动和分叉禁用，并给出可见原因。
  • 提交前比较：以提交前的文档为准严格比较，归档前就存在的组在本次提交里只允许改自己的 archived；比较使用归一化值（color/colorHex/图标/archived === true），宿主归一化不会误报；取消归档 + 编辑 必须拆两次，归档 + 编辑 合法。
  • 拖拽谓词：checkSessionDrop 与 checkGroupDrop/applyGroupDrop 共用规则；槽位按完整文档和稳定 id 解析，归档主体拒绝且不冒泡；非法目标不画占位符，部分剪枝不会放行提交阶段会拒绝的落点。
  • 宿主写入：store.commit 读取当前文档、按 group id 继承缺失的入站 archived，避免旧客户端整文档写入时静默取消归档；写前校验后再应用 before-state 不变量。
  • 控制接口：控制 API 新增 group.archive { groupId, archived }，同值写入是 no-change，类型/未知字段错误仍是 422；/commit 映射为 409 { ok:false, code:'archive-frozen', reason, groupId, field }；state.groups[] 暴露三个归档字段。
  • 界面细节：视图选项的两段三态都带标题，选择后浮层保持打开（Escape/点外部关闭），头部按钮同步两个筛选值；组行带 data-archived/data-path-only/data-contains-archived/data-structural-locked；灰显按整棵子树合成（嵌套组与会话行重置透明度，pathOnly 不灰）；归档确认弹窗、toast、带原因的禁用项、以及 archive-frozen 失败映射都已接好。
  • 同批 UI 补丁：归档确认弹窗新增默认关闭的「不再提示」、「恢复默认显示」改用紧凑的圆形还原图标。
  • 语言资源：19 种词典各新增 54 个键（331 → 385），其中 13 个是 CLDR 复数对象；归档三态、菜单、弹窗、拖拽、toast、空状态与搜索文案都已覆盖。

怎么用

1. 在分组菜单里归档整组

  1. 打开任意分组的菜单，选择「归档分组」。
  2. 核对确认弹窗：整组及子分组变为只读，不会修改会话的归档状态，分组也可能被当前筛选隐藏。
  3. 如不想再看到确认，勾选默认关闭的「不再提示」；取消或失败不会记住这个选择。

这一步把整组连同子分组收进归档，下图标出菜单入口与目标分组。

2. 视图选项里的分组归档三态

  1. 打开视图选项，找到「会话」与「分组」两段独立的三态。
  2. 在分组段选择「隐藏已归档分组 / 全部分组（显示已归档）/ 仅显示已归档分组」。
  3. 选择后浮层保持打开，可以连续设好两段；头部按钮同步显示两个筛选值。

这一步设置分组归档的可见性，下图对比旧版只有会话三态、新版多出分组三态。

3. 归档组灰显，结构操作被锁

  1. 归档组整行灰显并带锁标。
  2. 结构类菜单项（新建会话、新建子分组、重命名分组、更换图标、修改颜色、移到其他分组、上移/下移、删除分组）全部置灰，点击只提示「归档分组，此操作已锁定」。
  3. 「取消归档」始终可用。
  4. 组内会话仍可打开、改名、切换归档状态、复制 Session ID；拖拽、重排、移动、分叉被禁用。

这一步确认归档组的只读范围，下图对比旧版普通行与新版锁定状态。

4. 搜索命中隐藏分组时给出显式动作

  1. 搜索只命中被分组筛选隐藏的会话时，列表显示「1 个匹配会话被隐藏在已归档分组中」。
  2. 点「显示已归档分组」，分组筛选切到能看见归档组的状态。
  3. 命中的会话随后出现在结果里；头部计数与搜索共用同一套可见性，隐藏组里的会话不会被算进未分组。

这一步处理搜索命中隐藏内容的情况，下图是提示行与「显示已归档分组」按钮。

兼容性

分组归档是 DOC_VERSION 1 之上的增量契约，旧文档与旧宿主都有明确的降级路径。

  • 旧文档：archived 缺失读 false，不拒绝、不隔离。
  • 旧客户端 + 新宿主：宿主按 id 继承缺失标记，避免整文档写入丢状态。
  • 新客户端 + 旧宿主：字段通常能保留，但旧宿主不显示归档状态、不执行结构锁，只有客户端侧守卫生效。
  • 备份恢复：按原样写入（恢复路径的显式例外），恢复到归档前状态是允许的。
  • 降级：不认识该字段的宿主保留 JSON 中的 archived、隐藏归档 UI、跳过锁；重新升级后无需迁移即可恢复。
