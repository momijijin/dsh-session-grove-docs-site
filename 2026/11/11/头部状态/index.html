头部状态

当前适用版本：0.4.0-beta.65

自由分组标题行只有三个统计按钮：执行中、等待用户介入、未读。它们统计同一批会话的主状态，三态互斥：一个会话同一时刻只会落在其中一个计数里，也不统计后台任务。点任一按钮，下拉按分组列出对应会话，点条目直接打开。侧栏放不下时下拉会自动翻到另一侧，关闭后焦点回到按钮。

摘要

① 三个按钮：执行中（活动波形）、等待用户介入（暂停）、未读（信封），数字是当前计数。
② 下拉按分组分节，节标题是分组名或「未分组」，点会话直接打开。
③ 三态是互斥的主状态：待审批/计划待审/待回答 → 等待用户介入；运行中 → 执行中；已完成未读 → 未读。
④ 计数遵循分组归档筛选；被隐藏的归档组不计入。
⑤ 浮层按视口定位：窄侧栏向右翻边、短窗口限高并可在面板内滚动；关闭后焦点回到触发按钮。

三个按钮

1. 认按钮与计数

  1. 执行中：活动波形图标，统计正在跑的会话，包含只在跑子智能体的会话。
  2. 等待用户介入：暂停图标，包含待审批、计划待审、待回答三种交互。
  3. 未读：信封图标，统计已完成但还没读的会话。
  4. 计数为 0 时按钮与数字变淡；按钮提示会说明它统计什么，计数本身直接显示在图标旁。
  5. 侧栏进入紧凑态（约 390px 以下）时，计数为 0 的数字会暂时隐藏，图标与悬停提示仍在。

这一步看标题行右侧的三个统计按钮，示例里没有运行中的会话，三个计数都是 0。

2. 按分组看会话

  1. 点任一按钮展开下拉；浮层里有一行说明「执行中、待介入、未读三态互斥，不含后台任务」。
  2. 有会话时按分组分节：节标题是组名；未归组的会话归到「未分组」。
  3. 每条显示会话标题；已归档会话带「已归档」标记，点击只会提示「已归档会话不可打开」，不会打开会话。
  4. 点条目打开会话并收起下拉；没有对应会话时显示空状态，例如「没有正在执行的会话」。
  5. 面板优先贴在按钮同侧；侧栏窄到放不下时自动翻到另一侧，不会越出窗口。窗口变矮时按剩余空间限高，内容多就在面板内滚动。
  6. 按 Esc 或点外部关闭后，Tab 焦点回到刚才那个状态按钮。

这一步打开「执行中」的下拉，示例里显示空状态。

把侧栏拖到 264px 再点「等待用户介入」，面板会向右展开，从状态按钮下方伸进内容区，整块完整可见。

注意

三个计数只统计会话，不含后台 job。计数为 0 不代表下拉不可用，点开仍会显示对应的空状态文案。

互斥的主状态

3. 一个会话只算一种

  1. 主状态优先级：等待用户介入 > 执行中 > 仅子智能体运行 > 已完成未读 > 空闲。
  2. 同一会话不会同时出现在两个计数里，三个数字可以直接相加。
  3. 等待用户介入只认宿主的三种 pending：审批、计划审阅、提问。
  4. 执行中包含主会话运行与仅子智能体运行两种情况；只有子智能体在跑、主会话空闲时仍算「执行中」。
  5. 空闲会话不进入任何计数；已完成但已读的会话也不算未读。

展开：计数与筛选的关系

  • 头部计数与列表使用同一套分组可见性：被分组筛选剪掉的归档子树不计入。
  • 「仅显示已归档分组」下只统计归档组与通向它们的组头路径，未分组不计入。
  • 会话自身的归档筛选不影响计数；已归档会话仍会以「已归档」标记出现在下拉里。
  • 三个计数来自同一次遍历，主状态只取列表中的第一个，因此天然互斥。

下一步

  • 搜索与筛选：按标题、工作区或分组路径找会话，并处理归档结果。
  • 分组配置：多套命名配置之间切换，先看只读差异再确认。
