0.4.0-beta.59：新建会话的组内跟随

从分组组头新建的空白会话，在首次发送提示词前会一直跟着原分组走；切换工作区不会再把它留在「未分组」。这一版修的就是这个跳组问题，.59 让会话在首次发送提示词之前保持组内跟随。

摘要

① 组头新建的空白会话，在首次发送提示词前始终跟随原分组。
② 连续切换工作区、切到第三个再切回，也留在原组。
③ 发送提示词、手动移组、分组被删或持久化失败后，跟随立即停止。

改了什么

问题出在「新建后、发提示词前」这段空窗期：宿主切换工作区时会复用或新建空白会话，旧版没有把这层归属带过去。

  • 空白会话跟随原分组：从组头或分组菜单新建的会话会记住分组，切换工作区后仍在原组。
  • 旧占位不残留：被替换的旧占位会话同步移除，组里不会出现重复的「新会话」。
  • 连续切换也成立：切到第三个工作区再切回原工作区，会话依然留在原组。
  • 不闪旧分组：首次切换用乐观移动，避免界面先画出旧分组。
  • 验证结果：单元、契约与 UI 运行时测试全部通过，隔离宿主与全语言门禁也通过。
对比项 旧版（0.4.0-beta.58） 新版（0.4.0-beta.59）
新建会话后切换工作区 停在「未分组」 留在原分组
连续切换、切回原工作区 不跟随 仍留在原组
示例组「日常事务」会话数 3 4
示例未分组会话数 1 0
注意

跟随只在「首次发送提示词之前」生效。首次发送提示词、手动把会话移出分组、目标分组被删除或持久化失败时，跟随意图会立即清除，之后按普通会话处理。

展开：实现细节

  • 首次切换的移动：用布局阶段触发的乐观移动完成，不等活动会话变化后的普通提交，所以不会先画出旧分组、下一帧才跳到正确位置。
  • 同一工作区不抢位：点开另一个空白会话时，不会抢走组的位置。
  • 验证计数（2026-11-09）：529/529 单元与契约测试、15/15 UI runtime；社区与官方隔离宿主、ja 语言包与 23/23 全语言门禁通过。

怎么用

1. 从分组菜单新建会话

  1. 在任意分组的组头点 +，或打开分组菜单选「新建会话」。
  2. 会话会直接落在该组组头，并成为当前会话。
  3. 工作区按该组已有会话推断，不需要先切到官方侧栏再回来。

这一步从组头新建会话，下图以「日常事务」为例。

2. 切换工作区，会话仍留在原组

  1. 点主区域的「选择工作区」，切到另一个工作区。
  2. 回到自由分组视图，检查新会话的分组与未分组计数。
  3. 再切到第三个工作区并切回原工作区，确认结果相同。

这一步验证切换后的归属，下图直接对照旧版与新版。

内部改动

展开：跟随状态的实现

新增纯函数 src/core/new-session-follow.js：newSessionFollow 判断活动会话是否应跟随、是否要移除上一个占位会话，pendingFollowStillValid 校验跟随意图是否仍然有效。

客户端在组头创建成功后记录 groupId / trackedSessionId / workspaceId，每次活动会话变化时对账：只在「换到不同工作区的空白会话」时触发移动；移动与移除同处一个乐观提交，持久化失败则清除意图并保留原状。手动改组经 store 订阅立即取消跟随，卸载时一并清理。
